# 二狗输入法设计说明

这份文档整理前期讨论里仍然有效的设计结论，给想了解“为什么这样做”的读者和贡献者。实现进度和实测数据见 [PLAN-v1.md](PLAN-v1.md)，隐私承诺见 [../PRIVACY.md](../PRIVACY.md)，第三方组件见 [THIRD_PARTY.md](THIRD_PARTY.md)。文中的“D”是项目发起人。

## 1. 目标

一个隐私优先、开源的 macOS 中文输入法，能代替常见的云输入法日常使用：

- 五笔 86（极点码表）打字，五笔拼音混输；也可以只用拼音；
- 本机语音输入，中英混说；
- 打的字和说的话默认不出这台 Mac。唯一会把文字发出去的功能（云端整理）默认关闭，开之前写清楚发什么、发给谁；
- 代码全部公开（GPL-3.0），可以自己编译、自己审计。

和常见云输入法的取舍：

| 常见云输入法的做法 | 二狗输入法 |
|---|---|
| 候选可能经过服务器或过滤 | 候选只来自本机码表和本机用户词库 |
| 上传输入内容、上下文或统计 | 不上报任何输入、上下文或统计；没有遥测 |
| 输入法进程常驻联网 | 输入法进程没有网络权限，系统层面就不能联网 |
| 用户词库云同步 | 词库只在本机，不提供同步 |
| 剪贴板历史 | 不读剪贴板、不存剪贴板历史 |
| 语音传到服务器识别 | 语音在本机识别，录音不落盘、不出机器 |
| 闭源 | GPL-3.0 |

## 2. 技术选型

### 2.1 外壳：Swift + InputMethodKit

不从零写引擎。外壳用 InputMethodKit（Swift），结构参考[鼠鬚管](https://github.com/rime/squirrel)（GPL-3.0）。目前只参考结构，没有复制文件；以后借用要保留原版权头并在 THIRD_PARTY.md 记录。不选 Fcitx5-macOS：它是完整的输入法框架，体量远超需要。

### 2.2 打字引擎：librime + rime-wubi86-jidian

- 嵌入 librime（BSD-3-Clause，有 macOS universal 预编译包），码表用 rime-wubi86-jidian（MIT）。词库、调频、候选排序都交给 librime。
- 插件只用 librime-lua（混输的排序、自动上屏、五笔码提示、五笔容错、计算器、日期、常用语）。lua 脚本放在应用包里，算项目代码。
- **只调频、不自动造词**（五笔拼音混输）：`encode_commit_history` 会把连续上屏的字切成大量垃圾词，新词还会让原本唯一的四码变得不唯一，破坏“四码唯一自动上屏”。只开 `enable_user_dict` 时只调整已有词条的顺序，不改变“唯一”的判断。手动造词在设置里做。
- 拼音是默认方案（D 2026-11-10：五笔需求比较小众）；之前用过默认五笔的安装保持五笔（`SharedSettings.migrateDefaultScheme`）。
- 只用拼音模式是另一套方案（`ergou_pinyin_ime`），会像普通拼音输入法一样记住打过的句子，存在它自己的用户词库里，不混进五笔拼音混输。

### 2.3 五笔拼音混输

要求：不用切换、不用前缀就能混输；拼音候选旁显示五笔码（方便学码）；拼音支持模糊音和容错；五笔尽量能容错。

**核心冲突：四码唯一自动上屏会截断拼音。** 用极点码表和 `pinyin_simp` 统计：超过 4 个字母的拼音里，约 13%（按权重）前 4 个字母正好是一个唯一的五笔四码，开着自动上屏就打不出来（打 `shang`，到 `shan` 就被五笔上屏了）。反过来，唯一四码里约 5.8% 同时是合法拼音前缀。

结论：

- **四码唯一自动上屏是选项，默认关**。默认按空格或数字选词。
- **候选顺序按类型排，两种模式相同**：五笔码完全对上的 → 拼音 → 还没打完的五笔码 → 纠错，组内按词频（`lua/ergou/rank.lua`）。按词频混排时拼音会压住短的五笔码，把拼音整体降权又会让 `wo` 第一页没有“我”，都在真实 librime 上试过不行。
- 打开自动上屏后：只数五笔候选；四码唯一而且不是拼音前缀就上屏；是拼音前缀就等下一个键，还能拼成拼音就继续打拼音，否则上屏五笔字、把这个键当新码第一码（顶字）。另有严格模式：四码唯一就上屏。实际效果是像拼音开头的四码基本不自动上屏，要按空格。
- 先按 `` ` ``（反引号）再打，表示只打拼音。不用 `z` 前缀，因为混输时 z、zh 开头的拼音是直接打的。
- 拼音用 `script_translator`（支持模糊音和容错），五笔码注释用反查。
- 模糊音用拼写运算（`derive`）实现，设置里逐项勾选，默认开 z/zh、c/ch、s/sh、n/l、en/eng、in/ing。拼音容错用 librime 的 `enable_correction` 加几条常见打反规则。容错候选排在后面，不参与自动上屏。
- 五笔容错只在空码时触发（五笔和拼音都查不到）：试相邻键替换和相邻两码对调，结果标“纠”，永远不自动上屏。五笔码很密，正常码参与纠错会让候选全乱。

### 2.4 语音：sherpa-onnx，本机识别

- 运行时用 sherpa-onnx（Apache-2.0，C API，有 universal2 预编译包）。
- 两个模型：**Qwen3-ASR 0.6B**（Apache-2.0）出最终结果，准、认“我的词”热词；**SenseVoice Small**（FunASR 模型协议）速度快，用来边说边显示。只装一个也能用。实测（D 的声音，桌面稿）错字率 SenseVoice 3.9%，Qwen3-ASR 2.9%，加热词后 0.3%。
- SenseVoice 的权重是 FunASR 模型协议，不是开源许可证（要注明来源、不得无故诋毁、可单方修改）。所以模型不进仓库、不进安装包，由用户在设置里确认后下载，弹窗写明协议要点。识别引擎做成可替换接口。
- 交互：点一下右 Option 开始，再点一下结束；录音中 Esc 取消。有光标就直接上屏；没有光标就写进剪贴板并提示“已复制”。长录音在停顿处自动分段。
- 识别后整理（可选）：Apple 设备端模型、本机大模型（llama.cpp，实测改对的少、会乱改，不推荐），或云端大模型（效果最好，默认关，见 PRIVACY.md）。

## 3. 隐私与权限

### 3.1 拆成几个沙盒程序

| 程序 | 网络 | 负责 |
|---|---|---|
| 输入法本体 | 无 | 打字、录音、本机识别、候选窗、上屏、全局语音键 |
| 本机整理 XPC | 无 | Apple 设备端模型、llama.cpp |
| 云端整理 XPC | 只有 network.client | 只在用户选了云端时调用 |
| 设置程序 | 有 | 设置界面、用户点击后下载模型；检查更新（每天自动一次，可关）、用户同意后下载更新 |

- 输入法本体不写任何网络代码、不引入带网络功能的依赖，`scripts/check-no-network.sh` 检查源码和签名权限。
- 共享模型和设置用 App Group 容器（`<TeamID>.com.codamon.ergou`）。
- **Rime 用户目录不放 App Group，放在输入法自己的沙盒容器里**：librime-lua 会先从用户目录的 `lua/` 找脚本，用户目录里有 `rime.lua` 也会执行。如果有网络权限的设置程序能写这个目录，就能把代码注入能看到按键、能录音的输入法进程。所以设置程序只写共享设置里的值，输入法校验后自己生成 Rime 配置；用户目录里出现 `rime.lua` 或 `lua/` 就先隔离；模型加载前校验 SHA-256；清空调频通过通知让输入法自己做。

### 3.2 模型分发

用户点了才下载，下载前弹窗写明模型名、大小、来源、许可证；下载后校验 SHA-256。安装包和仓库都不带模型。

### 3.3 全局语音键和权限

- 右 Option，全局生效。用只监听、不拦截的事件监听（listen-only event tap），只需要“输入监控”权限，不需要辅助功能权限；不吞 Fn 或任何按键。
- 麦克风：只在开始说话后录音。
- 在别的输入法下说话：识别完临时切到二狗输入法、把结果打进当前输入框，再切回原来的输入法；约 0.5 秒内没有输入框接手，就当作没有光标，改写剪贴板。

### 3.4 密码框

安全输入状态下不录音、不出候选、不学习、不写剪贴板。

### 3.5 自动更新

D 2026-11-10 决定：**自动检查默认打开，安装前一定征得同意**。

- 输入法本体没有网络权限，不变。它在被激活时看一眼时间：自动检查开着、离上次检查超过 24 小时、设置程序没在运行，就在后台启动设置程序（`ErgouIME/Support/UpdateCheckScheduler.swift`）。要做什么不能用启动参数传：沙盒程序用 NSWorkspace 启动别的程序时，参数会被系统丢掉（实测，设置程序没收到参数，结果在用户打字时弹出了设置窗口）。所以输入法先在 App Group 设置里写一条带时间戳的请求（`SettingsLaunchRequest`），设置程序启动时取走，超过 30 秒的不算。菜单“打开设置…/关于”跳到哪一页也走这条路。
- 设置程序这时不进普通界面（`ErgouIMESettings/App/main.swift`），没有窗口、没有程序坞图标，只向 GitHub API 要一次最新发布（`ErgouIMESettings/Update/UpdateChecker.swift`）。没有新版本、或用户跳过了这个版本，就直接退出。
- 有新版本时弹窗，窗口浮在最上层但**不抢键盘焦点**（用户可能正在打字），这时才显示程序坞图标。点“下载并安装”才下载；核对 `.sha256`，再用 `pkgutil --check-signature` 核对：签名证书是 Developer ID Installer、团队就是本程序自己的 Team ID（取自 App Group ID）、并经过苹果公证。全部通过才用系统“安装器”打开，用户在安装器里再确认（`UpdateInstaller.swift`）。
- 不用 Sparkle：Sparkle 要另管一套 EdDSA 签名密钥，沙盒里还要加安装 XPC 和 mach-lookup 例外，而且要原地替换外层的输入法 bundle。我们的发布本来就是经过公证的 pkg，查 GitHub Releases、交给系统安装器，更简单，也让“谁能联网”和以前一样只有设置程序。代价是安装时要在安装器里点几下。
- 发布约定：tag 是 `v<版本>`，附件必须有 `ErgouIME-<版本>.pkg` 和 `ErgouIME-<版本>.pkg.sha256`（`scripts/release.sh` 生成），不能是草稿或预发布。

### 3.6 签名和分发

开发阶段就用固定证书签名（临时签名每次重编都会让麦克风和输入监控授权失效）。发布用 Developer ID 签名、Hardened Runtime、公证，安装包装到当前用户的 `~/Library/Input Methods`（`scripts/release.sh`）。

## 4. 功能取舍

- **做，只存本机**：语音识别记录（输入法自己的沙盒里，最近 200 条、30 天，可关；不存像密码、验证码、密钥的内容）。
- **做**：中英文之间自动加空格；按应用记住中英文；英文标点、全角；常用语；计算器和日期；联想；双拼；简繁切换；词库和设置的导入导出。
- **以后**：自定义语音快捷键（按住说话、免提）；翻译（云端，用户主动开启）；Whisper 备选引擎。
- **不做**：剪贴板历史；云输入和云端词库；跨设备同步；方言识别；手写。
- **暂缓**：符号自动配对（输入法没有移动光标的接口，要申请辅助功能权限模拟按键）。

## 5. 平台

- 最低 macOS 13 Ventura；从第一天就编 Universal（Apple 芯片 + Intel）。Intel 不单独优化，真机测试在公开发布前补。
- 以后可能支持 Windows 和手机：打字引擎（librime）和语音引擎（sherpa-onnx）都跨平台，Mac 端只做很薄的外壳；和 Mac 无关的逻辑不写进 InputMethodKit 相关的类。iOS 键盘扩展不能用麦克风、内存也紧，语音要跳到主 App 本地识别。

## 6. 风险

| 风险 | 应对 |
|---|---|
| SenseVoice 模型协议不是开源许可证，可单方修改 | 不随包分发；弹窗展示协议；默认推荐 Apache-2.0 的 Qwen3-ASR；保留可替换的识别引擎接口 |
| 输入法常驻内存，模型很大 | 按需加载，闲置 10 分钟释放 |
| 没有光标时写剪贴板会覆盖原内容 | 只在这种情况下写，提示“已复制”，PRIVACY.md 写明 |
| 云端整理把文字发出本机 | 默认关；开启前写清发送内容；密码框、终端、密码管理器不取上文 |
| 云端 Key 是文件不是钥匙串 | 目录 0700 / 文件 0600、不进备份；PRIVACY.md 写明代价；以后有描述文件再换钥匙串 |
| macOS 升级改变 InputMethodKit 或 TCC 行为 | 跟进鼠鬚管的修复 |
| `pinyin_simp` 词典较小 | 已处理（2026-11-10）：拼音大词库（雾凇拼音 base + ext，约 89 万词，GPL-3.0）改成在设置里确认后下载，两个方案都用；没下载时退回 `pinyin_simp`。腾讯词库（再加约 98 万词）是可选附加项：实测部署约 2 秒 → 4 秒、词典表 29 → 61 MB，少数整句更准（精力不足），也多了冷僻名称候选，所以默认不装。整句模型（octagram 语法模型）2026-11-11 做成可选下载，见下 |


## 整句模型（2026-11-11）

拼音整句只靠词频挑词，长句容易拼错。librime-octagram 插件用语言模型给词与词的搭配打分。用测试工具在 D 的 Mac 上实测：拼音方案 + 拼音大词库，121 个日常分句（6～20 字）打全拼，看第一候选是否整句正确；每个模型用发布者推荐的参数。

| 模型 | 文件 | 整句全对 | 字准确 | 内存峰值 | 每键耗时 |
|---|---|---|---|---|---|
| 不用 | — | 65.3% | 94.5% | 37 MB | 0.38 ms |
| 官方 bgc-compact（按字） | 10 MB | 33.9% | 87.3% | 47 MB | 0.52 ms |
| 官方 bgc（按字） | 29 MB | 33.9% | 87.3% | 65 MB | 0.48 ms |
| **官方 bgw-compact（按词）** | 41 MB | **81.0%** | 97.5% | **76 MB** | 0.56 ms |
| 官方 bgw（按词） | 206 MB | 81.8% | 97.9% | 226 MB | 0.54 ms |
| **万象 LMDG** | 418 MB | **82.6%** | 98.3% | **391 MB** | 0.55 ms |

- 按字的模型是给单字词库用的，配大词库反而变差，不用。
- 官方 bgw-compact、bgw 和万象只差 1～2 句，错的句子各不相同。万象换成官方的参数后降到 77.7%，所以每个模型用自己的推荐参数。
- 一个方案只能挂一个语法模型，所以设置里是**二选一**（D 2026-11-11）：“轻量”（bgw-compact，推荐）和“万象”（略准，但多占约 350 MB 内存，界面上警告）。bgw 全量比轻量大 5 倍只多对 1 句，不提供。
- 输入法把下载的 .gram 拷进自己的 Rime 用户目录、校验副本后才写进方案（插件会 mmap 并解析它），再删掉下载的原文件省空间，`VERSION` 留作“已安装”标记（`ErgouIME/Engine/GrammarModel.swift`）。两个方案（拼音、五笔拼音混输的拼音部分）都用。

## 新手引导、个人词库、联网记录（2026-11-11）

D 定的三件事，目标是“换得过来”和“隐私看得见”。

- **新手引导**（`ErgouIMESettings/Views/WelcomeView.swift`）：输入法第一次被激活时，用 `SettingsLaunchRequest.welcome` 在后台启动设置程序（不抢焦点）。设置程序显示引导时写 `welcomeShown`，以后不再弹；“关于”里可以重开。四步：输入方式 → 推荐下载（拼音大词库、轻量整句模型、两个语音模型；每项列名称、大小、来源、许可证、SHA-256，点“下载”就是确认，依次下载）→ 个人词库 → 语音说明和试打框。老用户升级后也弹一次，已装的项显示“已安装”。
- **个人词库**（`Shared/ImportedWords.swift`、`ErgouIMESettings/Model/PersonalDictionaryImporter.swift`）：读用户在打开面板里选的文件（`files.user-selected.read-only`），认 UTF-8 / UTF-16 / GB18030 的文本词库（搜狗 `'ni'hao 你好`、QQ / 百度 / Rime 各种列序、纯词表）和 macOS 文本替换 plist（变成常用语）。只收 2～16 个汉字的词；拼音音节数对得上才保留，否则交给 Rime 按单字读音自动注音（测过多音字两种读法都能打）。设置程序写 `Imported/pinyin-words.txt`，输入法再校验一遍，生成 `ergou_imported`（带拼音）和 `ergou_imported_auto`（`columns: [text, weight]`）两张表，排在拼音词典导入列表最后：主词库已有的词保持原权重，新词权重 50000（约雾凇词条第 95 百分位）。五笔码表不受影响。
- **联网记录**（`Shared/NetworkLog.swift`、`ErgouIMESettings/Views/NetworkLogView.swift`）：设置程序（下载、检查更新、下载更新和校验值）和云端整理进程（每个 HTTP 请求，包括结构化失败后的重试）在请求结束时各写一行 JSON 到 App Group，O_APPEND 单次写入。记时间、程序、用途、服务器和路径（不含查询串）、“发出了什么”（只记数量和字数）、收发字节、结果。下载记的是实际应答的服务器（GitHub 会从 github.com 跳转到下载服务器），并注明跳转。保留 1000 条。它是联网程序的自述，不是防篡改审计，界面和 PRIVACY.md 都写了怎么用 nettop / 防火墙独立核对。
